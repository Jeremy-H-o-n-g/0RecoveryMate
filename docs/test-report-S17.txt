Design notes (S17 do-not-do honored):
- Exactly ONE timer per session, owned by useExerciseSession (wraps the S16
  useExerciseTimer). Session controls delegate to the <video> element; media
  events drive phase + timer through the idempotent syncTimerToPlaying, so the
  control path and the event path can never double-start the timer.
- Native media errors are surfaced with a role=alert and a safe paused state;
  they are never suppressed. A rejected play() (non-AbortError) is surfaced too.
- No forced auto-advance anywhere: a completed step timer or an ended video only
  informs; the user taps Next step (S17 safety: do not force the next movement).
- No completion effects (that is S18).
- Step timer is per-step (stepDurationSeconds, from exercise.durationSeconds
  until reviewed content defines per-step timing - S11/S13). Changing steps
  gives the new step a fresh timer; if the session is playing it restarts.
- ExerciseSession renders its own <video> because the session needs direct
  media-event access; the S15 accessibility rules are preserved (native
  controls, no autoplay, captions, transcript, graceful fallback). Unifying
  with VideoPlayer is S19 integration work (S17 file allowlist excludes it).
